## 一、这是个什么东西

**人话**：在你自己的电脑或服务器上跑一个程序，把「DeepSeek 网页版聊天」变成正规的 AI 接口。之后写代码用的 Claude Code、聊天用的 Cherry Studio、Open WebUI 等工具都能直接连它，像用付费官方 API 一样——用的是 DeepSeek 网页免费额度。

**术语**：一个自托管的反向代理网关。它持有你的 DeepSeek 会话凭据，对外暴露标准 OpenAI / Anthropic 端点，内部负责会话映射、PoW 挑战求解、多账号轮转、上下文滚动压缩等全部工作。

⚠️ 自动化使用违反 DeepSeek 服务条款。请只用专用小号，账号可能随时被禁言或封禁，风险自负。

## 二、五分钟跑起来

### 1. 安装并启动

```bash
uv sync
cp .env.example .env
# 编辑 .env：至少改掉 DEEPSEEKER_ADMIN_PASSWORD 和 DEEPSEEKER_API_KEY
uv run deeperseeker
```

Docker：

```bash
cp .env.example .env
docker compose up -d
```

浏览器打开 `http://localhost:4000/`，用 `.env` 里的面板口令登录。

### 2. 添加第一个账号（**最关键的一步**）

面板右侧「添加 DeepSeek 账号（推荐）」：

1. 填**邮箱或手机号**、密码
2. 填入**设备指纹**（见下）
3. 点「登录并加入号池」

**为什么不用「粘贴浏览器 Token」**：2026 年 11 月起，上游会整体吊销「浏览器出生、拿到别处用」的会话——粘贴的令牌往往几分钟内失效，浏览器那边也一起被登出，表现为频繁封号、越用越要重新提取。桥内登录让会话直接出生在本服务里，令牌失效时还能自动重登。粘贴入口只留作应急。

**设备指纹怎么拿**（一次即可）：

1. Chrome 打开 `chat.deepseek.com`，**不用登录**，等页面完全加载
2. F12 → Console，执行 `SMSdk.getDeviceId()`
3. 把输出的那串 base64 复制到面板的「设备指纹」框

真实安卓 App 登录时请求体携带的就是数美（SMSdk）生成的指纹；随机或伪造的 UUID 会被风控以 `RISK_DEVICE_DETECTED`（`biz_code=11`）拒绝。留空时桥会依次尝试：该账号已保存的指纹 → `DEEPSEEKER_DEVICE_ID` → 本机缓存 → 无头浏览器自动采集 → 结构化占位（最后这档大概率登录失败）。**同一账号请始终用同一个指纹**，桥会记住并在自动重登时复用。

### 3. 接上你的 AI 工具

- **OpenAI 兼容**：Base URL `http://localhost:4000/v1`，API Key 填 `.env` 里的 `DEEPSEEKER_API_KEY`
- **Anthropic 兼容**：Base URL `http://localhost:4000`
- **模型**：`v4.1flash`（传别的名字也会被归一化到它）

## 三、面板功能速览

| 区域 | 你能做什么 |
|---|---|
| 账号列表 | 看邮箱/手机号、状态、设备指纹是否已绑定、最近登录 |
| Token 号池 | 看「桥内 / 浏览器」来源徽章、状态与**五态说明**、在途占用、轮换转移、最近检查；可逐个或全量「检查」 |
| 人工恢复 | 隔离的账号点「恢复」显式放回轮换 |
| 功能开关 | 开关提示词增强（`reasoning_effort=max` 时是否附加强化指令），即时生效 |
| 检测链路 | 只读探测「面板 → 上游」是否连通，不创建会话、不发消息 |
| 接口信息 | OpenAI / Anthropic 地址与默认模型 |
| 使用统计 | 顶部导航「使用统计」：逐小时用量、峰谷计价、缓存命中率 |

号池表每 3 秒局部刷新状态、占用、转移、最近检查四列，不会打断你正在填的表单。

## 四、状态都是什么意思

| 状态 | 含义 | 你该做什么 |
|---|---|---|
| 🟢 有效 | 正在轮换中，能正常干活 | 不用管 |
| 🔵 被限流 | 请求太频繁，冷却中 | 自动恢复，不用管 |
| 🟠 确认禁言 | 上游明确说账号被禁言（附解禁时间） | 解禁前发不了消息；解禁后点「恢复」 |
| 🔴 已失效 | 令牌过期或被登出 | 重新用桥内登录添加账号；点「恢复」没用 |
| ⚪ 已隔离 | 其他原因退出轮换 | 看说明列与悬停提示，确认正常后点「恢复」 |

**「检查」做了什么**：用只读的 `users/current` 问上游每个令牌的真实状态——正常、禁言到几点、已作废。它不创建聊天会话、不发送任何模型消息。确认禁言会自动隔离；解禁后再次检查会自动恢复。

**「检测链路」做了什么**：同样只读地问一次上游，用来确认「面板到 DeepSeek」这段通不通。它不代客户端试发消息，客户端真实可用性还是以实际发一条为准。

## 五、数据会不会丢

- 号池、账号密码（加密后）、设备指纹都存在本地 SQLite；Docker 部署时位于 `/app/data` 持久卷
- 容器重建且没挂持久卷时，可以启用**加密灾备**：在 `.env` 设置 `DEEPSEEKER_BACKUP_SECRET` 与 `DEEPSEEKER_BACKUP_TARGET`（`telegram` / `gist` / `file`）。启动时若发现号池为空，会自动从备份恢复；本地有数据时绝不覆盖
- 备份快照按真实列导出 `tokens` 与 `accounts` 两表，重登所需的凭据与指纹一起带走
- 未配置备份密钥时该功能完全静默，不产生任何网络请求

## 六、常见问题

**Q：登录提示「设备指纹被拒 / biz_code=11」？**
换一个真实指纹：Chrome 无痕窗口打开 `chat.deepseek.com`，F12 → Network 过滤 `users/login`，真实登录一次，复制该请求 Payload 里的 `device_id` 值。这一次登录产生的浏览器会话之后会被吊销，属正常现象。

**Q：令牌一直掉线、浏览器也跟着退出登录？**
说明你用的是「粘贴浏览器 Token」。改用「添加 DeepSeek 账号」的桥内登录，并删掉旧的浏览器令牌。

**Q：账号被禁言了怎么办？**
禁言会被自动识别并隔离，等解禁时间点「恢复」即可（或再点一次「检查」自动恢复）。不要用主号，也不要试图绕过限制。

**Q：回答写到一半断了？**
上游偶发抖动时服务端会自动续写并重试；仍失败时重发这一条消息即可。

**Q：`x-hif-leim` 要不要开？**
默认关闭。它是网页前端的风控头，抓包显示安卓 App 从不发送；本桥用安卓请求头，带着反而构成混合身份信号。除非你明确知道需要，否则保持 `DEEPSEEKER_HIF_ENABLED=0`。

## 七、安全须知

- 改掉默认面板口令和 `DEEPSEEKER_API_KEY`，尤其服务绑在公网时
- 令牌等同账号本体，不要发给任何人；`account_secret.key` 已在 `.gitignore` 中
- 建议只绑定本机（`HOST=127.0.0.1`），远程访问请套 VPN / 反向代理 + HTTPS
- 面板密码别用弱值，别搭建公共转发站

有问题去看仓库的 Issues，或在项目 README 里找更完整的配置说明。
